## 이번 작업 범위

선택한 구호소 **한 곳**, 출발 창고 **한 곳**에 대해 어느 트럭이 어떤 품목을
얼마나 싣고, 언제 출발해 어느 도로 구간을 거쳐 도착하고, 어느 경로로 돌아와
다음 운행에 사용될지를 결정한다. 트럭별 적재량은 경로·시각 선택과 **동일한
MILP**에서 결정한다. 먼저 물품 총량을 정하고 나중에 트럭에 임의로 나누지 않는다.

이번 변경은 모델과 입력/출력 계약, 검증, 개발 문서에 한정한다. 새 지도 화면,
최종 발표자료, 운영 배포는 포함하지 않는다. 기존 주간 노선 모델과 예측 모델은
유지한다. `/optimize`의 기존 `logistics` 객체에 아래 도로망 입력을 전달하면 된다.

원본 관리 기록에 함께 보존해야 한다.

## 시간과 수요의 연결

- `planning_start`: 시간대 오프셋을 포함한 ISO 8601 기준 시각. 내부·출력은 UTC.
- `slot_minutes`: 60을 나누는 1~60분 정수. 선택적 `slot_seconds`는 60을 나누는
  1~60초 정수이며 이때 `slot_minutes=1`이어야 한다. 공식 도로 시나리오 가져오기는
  짧은 구간의 누적 반올림을 줄이려고 5초를 사용한다. 이동·상차·하차·휴식·회차 시간과
  조달 리드타임은 슬롯 수로 **올림**한다. 잔여 유통기한은 **내림**한다.
- `*_hour`: 기준 시각 이후 **경과 시간**이다. 슬롯 격자와 정확히 일치해야 한다.
  현지 시계의 일광절약시간 변경은 자동 변환하지 않는다. 외부에서 확정 시각을
  UTC 경과 시간으로 바꿔 입력한다.
- 계획 주는 고정 168시간 단위다. `delivery_deadline_hours[w]`는 해당 주 안에
  있어야 하며 그 주 끝 시각은 허용한다. 주간 수요는 이 명시적 배분 납기에
  평가한다. 실제 일별 수요를 복원한 것은 아니다.
- 도착은 차량이 현장에 도착한 시각, 수요에 사용할 수 있는 시각은 **하역 완료**다.
  하역 완료가 주 1의 납기보다 늦으면 주 2 이후의 재고가 된다.
- 주문 주 `o`의 시작 시각 + 조달 일수 이후에 **상차 시작**해야 한다. 여러
  주문 주의 물품을 같은 트럭에 함께 실을 수 있으나, 품목·주별 공급 한도는
  모든 트럭/출발/경로 대안에 공유된다.
- 새 발주의 잔여 기한은 트럭 **출발 시각**부터 계산한다. 납기와 만료 시각이
  같으면 사용할 수 없다. 미래 납기까지 남는 물품의 만료·격리·폐기도 추적한다.
- 기존/선예약 배치의 `expiry_week`는 이전과 같은 첫 사용불가 주이며, 이 모드에서는
  그 주의 납기 시각을 만료 경계로 해석한다. 새 배치는 슬롯 만료 시각을 보존한다.
  FEFO는 그 경계/실제 슬롯 만료 순서를 따른다. 정확한 제조 배치 날짜가 있는
  기존 배치는 별도 일시 입력 확장이 필요하다.
- 창고 용량은 주별 수령 물품을 한꺼번에 받은 뒤 배분하는 보수적 피크로
  검증한다. 일중 교차 입출고로 더 많은 물품을 처리할 가능성을 주장하지 않는다.

**이 모드에서는 이전 모델의 `ceil(조달일수/7)+ceil(운송일수/7)` 규칙을 쓰지 않는다.**
예를 들어 조달 2일, 운송 2시간은 슬롯과 실제 납기 안에서 같은 주에 전달할 수 있다.

## 경로 탐색과 최적화 수식

기본 소규모 모드의 방향 그래프 `G=(V,E)`에서 각 트럭의 높이·폭·유형·빈 차량 중량으로 통행 가능한
모든 **단순 경로**를 창고→구호소와 구호소→창고 각각 탐색한다. 일방통행은 역방향
간선이 없다는 뜻이며 반대 방향을 자동 생성하지 않는다.

각 트럭, 입력된 출발 슬롯, 모든 왕복 경로 조합을 대상으로 시간표를 계산한다.
선택적 `path_search={method:"k_shortest",k:2,metrics:["distance","travel_time"]}` 모드는
각 기준의 상위 k개 단순 경로 합집합만 사용한다. 이 모드의 최적성은 **그 후보
집합 안에서만** 성립한다. 전체 도로망 최적성을 주장하지 않으며 운영 시간 창이나
적재 한도가 다른 유용한 우회로가 후보 밖에 있을 수 있다.
왕복 전체를 미리 살펴 운전 블록 상한 전에 도달 가능한 가장 늦은 허용 휴식
노드에서 휴식을 삽입한다. 필요하면 도착 이전에도 쉬며, 하역 자체는 휴식이 아니다.
이 정책은 도로 시간 창을 맞추기 위한 모든 선택적 휴식 시점을 열거하지 않는다.
따라서 다른 휴식 시점을 쓰면 가능한 운행이 후보에서 빠질 수 있다. 단일 간선이
운전 블록보다 길면 그 경로는 불가능하므로 중간 휴식 지점을 노드로 나눠야 한다.
구간의 전체 이동 시간 동안 도로가 열려 있어야 한다. 임의의 도중 대기는 없다. 이동 시간은 입력 구간별 고정값이며 시각별 혼잡 예측은 없다.
출발 시각 변경과 우회 경로가 모델의 시간·경로 대안이다.

이렇게 얻은 운행 대안 `c`마다 이진 선택 변수 `z[c]`를 두고, 품목 `i`, 주문 주
`o`마다 해당 운행에 싣는 양 `q[i,o,c]`를 함께 결정한다. 식량·키트·담요는 정수,
물은 기존 수요 단위인 L의 연속량이다. 물 한 병의 개수나 식량 박스의 개수를
출력한다고 해석하지 않는다. 포장 단위를 원하면 단위 및 수요 변환이 추가로 필요하다.

핵심 제약:

```text
sum(o,i) 포장포함_중량[i] * q[i,o,c] <= 유효_적재중량[c] * z[c]
sum(o,i) 부피[i] * q[i,o,c] <= 트럭_부피[c] * z[c]

유효_적재중량[c] = min(차량 payload,
                       차량 최대 총중량 - 공차중량,
                       모든 적재 운행 간선의 최대 총중량 - 공차중량)

sum(c) q[i,o,c] <= 품목 i, 주문 주 o의 공급량
sum(시각 t에 같은 트럭을 점유하는 c) z[c] <= 1
sum(자원 r에 슬롯 t에 진입하는 c) 진입횟수[c,r,t] * z[c] <= 예약가능횟수[r,t]

sum(근무창 안의 c) 운전분[c] * z[c] <= 근무창 운전한도
sum(해당 주에 발생하는 운전분) <= 주간 운전한도
sum(연속한 두 계획 주에 발생하는 운전분) <= 2주 운전한도

구매비 + 왕복 운송비 + 폐기비 <= 총예산
```

차량 점유는 상차 시작부터 운전·휴식·하차·복귀·창고 휴식·회차 완료까지다.
창고에 휴식 시설이 있으면 **운행마다 복귀 후 별도 휴식**을 붙여 다음 운행에서
연속운전 누적을 초기화한다. 상차나 회차 작업을 휴식이라고 간주하지 않는다.
창고가 휴식 노드가 아니면 트럭/기사 한 근무창에 운행 하나만 허용한다.

도로의 `capacity_resource`는 **슬롯별 진입 횟수**다. 동시에 구간 안에 있는
차량 수를 뜻하지 않는다. 양방향 도로·같은 국경/교량의 간선에 같은 자원 ID를
붙이면 공유한다. **빈 차량 복귀에도 적용**하며 자원을 왕복으로 통과하면 각각
차감한다. 빈 복귀는 공차 중량 제한과 높이/폭/차종/개방 조건을 만족해야 한다.
기존 예약 운행은 가용 차량 시간과 자원 슬롯에서 미리 차감한다.

품목별 납기 수요·주간 재고 보존·FEFO·만료·격리·폐기·격리 물품의 창고 점유는
기존 물류 모델과 동일한 MILP에 들어간다. 선예약 `pipeline_lots`는 이미 운송비와
차량을 예약한 외생 도착이다. 이 배치에 새 트럭을 만들어 이중 청구하지 않는다.

목적함수는 순서대로 고정한다:

1. 공정성 모드의 최대 미충족률 최소화
2. 품목 수요로 정규화한 가중 미충족 최소화
3. 구매+왕복 운송+폐기 총비용 최소화
4. 폐기/격리 최소화
5. 운행 수 최소화
6. 운전 시간 최소화
7. 출발 슬롯 합 최소화

운송비는 `fixed_trip_cost + cost_per_km * 왕복거리 + 왕복 통행료`다. 비용 입력은 모두 총예산과 동일한 통화/단위를 사용한다. 운전·납기에
불리한 저렴한 경로가 서비스 목표를 해치면 먼저 서비스 목표를 만족하는 경로를 고른다.
입력된 솔버의 시간·gap·수치 허용오차를 결과에 기록하며, 제한 안에서 솔버가 성공하지
못하면 실행 가능한 최적 계획이라고 반환하지 않는다.

## 입력 계약

`logistics` 루트 공통 키는 `item_weight_kg`, `procurement_lead_days`,
`shelf_life_days`, `initial_lots`, `pipeline_lots`, `disposal_cost`, `disposal_capacity`.
도로 모드에서는 `road_network`를 더한다. `vehicles/routes/corridors`와 **동시에
입력하지 않는다**. 이전 모드는 그대로 그 세 키를 사용한다.

`road_network`의 필수 필드:

| 필드 | 의미 |
|---|---|
| `planning_start`, `slot_minutes` | 기준 일시와 시간 해상도 |
| `destination_site` | 상위 `selected_site`와 동일 |
| `depot_node`, `destination_node` | 서로 다른 선언 노드 ID |
| `nodes` | `{id, label, rest_allowed}` 목록 |
| `edges` | 방향 간선 목록, 아래 필드 필수 |
| `trucks` | 실제 구분 가능한 트럭 ID 목록, 아래 필드 필수 |
| `departure_hours` | 모델이 선택할 수 있는 출발 슬롯 목록. 연속 시간 전체가 아님 |
| `delivery_deadline_hours` | 모든 계획 주에 대한 배분 납기 |
| `capacity_resources` | ID → `{start_hour, end_hour, max_entries}` 창 목록. 선언되지 않은 시간의 가용 횟수는 0 |
| `data_kind`, `sources` | `synthetic/operational`과 `{id,publisher,url,retrieved_at}` 목록 |

간선 필드:
`id`, `from_node`, `to_node`, `road_name`, `distance_km`, `travel_minutes`,
`toll_cost`, `max_gross_weight_kg`, `max_height_m`, `max_width_m`,
`allowed_vehicle_types`, `allowed_items`, `open_windows`, `capacity_resource`, `source_id`.
총중량은 **공차+화물**이고 허용 품목은 적재 운행에 적용한다.
`open_windows`는 `{start_hour,end_hour}` 목록으로 구간 전체 이동을 포함해야 한다.
`capacity_resource`와 합성 간선의 `source_id`는 null 가능하다.

트럭 필드:
`id`, `vehicle_type`, `payload_kg`, `tare_kg`, `max_gross_weight_kg`, `volume_m3`,
`height_m`, `width_m`, `loading_minutes`, `unloading_minutes`, `turnaround_minutes`,
`fixed_trip_cost`, `cost_per_km`, `max_continuous_driving_minutes`, `break_minutes`,
`max_weekly_driving_minutes`, `max_two_week_driving_minutes`, `availability`.
`availability`는 `{start_hour,end_hour,max_driving_minutes}`의 승인된 근무창 목록이다.
한 트럭에 한 기사가 배정되어 있다는 가정이다. 별도의 기사 공유/교대 최적화는 없다.

모든 시간 창은 시작 포함·끝 제외다. 값은 유한한 비음수이며 이동 시간·물품
중량·차량 부피 등은 양수다. bool을 숫자로 허용하지 않는다. 창은 겹치면 거부한다.
잔여 유통기한은 계산 범위를 위해 1,000,000일 이하로 제한한다.

## 출력 계약

`truck_plan`의 **한 행은 선택된 개별 트럭 운행 하나**다:

- `trip_id`, `truck_id`, `vehicle_type`, 출발/도착 노드, 구호소
- `cargo`, `cargo_units`, `cargo_lots`의 품목·수량·주문 주·만료
- `load_start_at`, `departure_at`, `arrival_at`, `delivery_complete_at`
- `return_at`, `available_again_at`
- `outbound_edges`, `return_edges`, `route_nodes`
- `weight_kg`, `volume_m3`, 각 적재 한도
- `round_trip_distance_km`, `driving_minutes`, `transport_cost`
- `timeline`: 상차, 각 간선의 진입/진출, 휴식, 하차, 복귀, 회차의 실제 슬롯 시각

`transport_plan`은 이 운행을 요약하고 `order_plan`은 동일 `trip_id`와 연결된다.
`road_capacity_usage`에는 복귀를 포함한 자원별 진입 시각·사용/한도가 남는다.
`model_info`에는 공식 구조 근거, 그래프 출처, 탐색 범위, 후보 수, 납기,
시간 해상도, 솔버 각 단계 결과와 한계가 기록된다.

검증 후 반환한다: 전체 선형 제약과 목적값 고정, 정수성, 트럭별 적재,
시간 점유/중복 배차, 구간 개방·중량·휴식, 도로 자원, 기사 근무창/주간 한도,
납기/만료, 운송비 합계를 재확인한다. 실제 도로가 닫혔거나 복귀 경로가 없으면
허구의 경로 대신 미충족 수요와 빈 `truck_plan`을 반환할 수 있다.

## 탐색 범위와 규모 제한

기본 모드는 입력한 작은 승인 도로망에서 모든 단순 왕복 경로와 출발 슬롯을
열거한 후 공동 최적화한다. 최단 경로 하나 또는 상위 k개만 골라 다른 대안을
조용히 버리지 않는다. **전국의 모든 도로와 연속 출발 시각에 대한 최적성은
주장하지 않는다.** 임의 순환 경로, 도중 자율 대기, 여러 목적지 순회 배송도 없다.

현재 상한: 노드 32개, 간선 128개, 트럭 24대, 출발 시각 128개, 각 방향의
단순 경로 256개, 평가하는 경로 조합 100,000개, 실행 가능한 운행 대안 4,096개, 발주 배치 변수 1,024개, FEFO 누적 항 1,000,000개.
초과하면 입력 오류로 중단한다. 후보를 자르거나 근사 결과를 정확해 보이게
표시하지 않는다. 규모 안에서도 재고·FEFO 정수 문제가 어려우면 솔버 시간 제한으로
중단할 수 있다. 실제 전국 데이터를 쓰려면 현장과 무관한 가지를 제거하고
검증된 도로 구간을 축약한 승인망이 필요하다. 향후 대규모 모델은 시간 확장
네트워크/열 생성 등 별도 설계와 검증 대상이다.

명시적 k 후보 모드의 입력 상한은 노드 100,000개, 방향 간선 250,000개,
좌표점 합계 5,000,000개, 출처 256개, 기준당 k≤8이다. 탐색 작업 한도, 운행 후보 한도,
발주 변수/FEFO 한도는 별도로 적용하고 초과 시 중단한다. 세부 입력과 가져오기
절차는 `poland_road_data.md`를 따른다.
