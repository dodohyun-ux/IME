## 요청한 네 단계의 확인

1. 학습된 모델 객체 3개가 정상 로드돼 실제 predict 호출을 수행한다. 원본 데이터셋과 정확히 같은 자료로 학습했는지, 시간 분리/누수가 적절했는지는 제공 학습 코드와 데이터 manifest가 없어 독립 증명하지 못했다. 제공 백엔드의 학습 종료일은 2025-05-09라는 선언이며 joblib에는 학습 종료일 필드가 없다.
2. UI의 3개 거점×최근 8주 입력은 기준 주부터 과거 순이다. 주간 합계를 7로 나누어 해당 주의 7일로 펼치고, 모델에는 과거→최근 순의 56일 이력을 넘긴다. 저장 자료가 없는 주는 빈칸으로 제공하고 실제값을 모두 입력하기 전에는 예측하지 않는다. 현재 완료된 최근 주까지 수동 입력을 허용했다.
3. 기준 주 종료 다음 월요일부터 28일을 예측한다. 하루의 예측을 다음 날의 유입 이력으로 추가하는 재귀 방식이며 7일씩 더해 4주 값을 만든다. 실제 추정기의 28회 호출, 첫 예측의 요일/월·최근 lag1/lag14·둘째 날 피드백을 검사했다. 미래 실제값을 바꿔도 예측은 변하지 않는 누수 방지 검사도 통과했다. /predict는 저장 백테스트 재생 없이 매번 이 모델을 호출한다.
4. 거점별 4주 예측값을 변형 없이 /optimize로 전달한다. 이용률로 산정한 이용자를 올림한 뒤 물·식량·위생키트·담요 수요를 만들고, 기존 조달/재고/기한/폐기·차량·공식 도로 배차 모델을 푼다. 입력–수요 일치와 실제 출력의 물류 제약을 별도 재검산했다.

3개 거점×8개 주를 각각 2배로 바꾸는 24개 실험을 수행했다. 다른 거점의 예측은 바뀌지 않아 거점 입력 연결이 분리돼 있음을 확인했다.

## 신뢰성에 대해 말할 수 있는 범위

기준 주 1개·거점/시점 12점의 실제값을 대조했을 때 새 모델 WAPE 13.34%, 직전 주 반복 기준선 14.81%, MAE 243.58명이다. 이는 한 번의 회고 비교일 뿐 독립 검증 세트의 모델 성능으로 일반화하면 안 된다. 번들의 구간 보정 근거가 2025-05-05~2026-01-19 기준주이고 목표 기간이 겹칠 수 있어 이번 80% 구간 적중을 독립 검증으로 주장하지 않는다.

새 번들에 WAPE/독립 검증 성적표가 없어 이전 주간 모델의 WAPE 10.88%·80% 구간 적중 80.56% 표시를 제거했다. 번들의 총 유입 잔차 보정 구간만 적용하며 구호소별 80% 구간을 새로 만들어내지 않았다. UI에 분쟁 입력이 없어 번들의 전형적 분쟁 수준을 사용하고 미래에도 유지한다. 실제 최신 분쟁 상황을 반영한 예측은 아니다.

원자료와 다른 수정 입력은 수정 시나리오 출처로 표시하고 미래 실제값 대조를 끈다. 저장된 실제값이 있는 원자료 입력일 때만 그 날짜의 실제값을 표시하며 추론에는 넣지 않는다. 수동 편집 예측은 별도 출처다.

실제 대응 운송 기록은 여전히 0건이다. 배송시간·지급비·현장 효과, 현재 창고/시설 운영 및 트럭 진입 적합성은 입증하지 않았다. 모든 운영 판정은 operational_ready=false이다. 최적화는 단일 창고–선택 구호소와 확보 도로/출발 후보의 조건부 계획이다.
