# 기준 주 분쟁 입력 연결 확인 — 2026-10-07

요청 범위: 현재 모델에 맞는 분쟁 입력을 UI에 복원하고 기존 예시 버튼·예측·최적화 흐름에 연결한다. 가중치 재학습이나 새 예측 성능 평가를 수행하지 않았다.

## 현재 입력과 반영 범위

- 난민 유입: 기준 주/1주 전, 세 거점별 2주 합계.
- 분쟁: 같은 기준 주의 우크라이나 전체 사건 수(건)와 사망자 수(명). 빈칸·음수·비정수이면 UI에서 예측을 막는다. 예시는1000건/100명으로 채운다. 예시 유입은 Medyka2000/1800,Dorohusk1600/1450,Korczowa1350/1200명이며 기준 주2026-01-26이다. 전부 가상 시연값이다.
- 제공 모델 분쟁 시차는 Medyka2일/Dorohusk1일/Korczowa2일이며 현재 수준·7일 평균도 사용한다. 주간 합계를 일별 동일 값으로 펼치므로 기준 주 이전의 분쟁 입력은 현재 특징에 들어가지 않는다. 미래에는 기준 주 수준을 유지한다.
- API conflict는 이제1행 또는 기존4행을 허용한다. 1행은 기존 제공 엔진의4행 내부 계약에 맞춰 반복한다. 새로운 과거 관측을 확보했다는 의미가 아니며 현재 특징의 수치/가중치를 보존하는 어댑터다. 모델 파일이나 relief_forecast.py 추론식은 수정하지 않았다.
- API 응답에 사용자가 보낸 분쟁 입력·실제 반영1주·입력/기본 가정 모드를 기록한다. 입력한 경우에는 잘못된 “현재 UI는 분쟁을 입력하지 않는다” 안내가 나오지 않는다. 분쟁 없는 이전 API 요청은 기존 전형적 수준 가정을 유지한다.
- 분쟁 변경 시 이전 예측/최적화와 비동기 응답을 무효화한다. 날짜 선택 때 분쟁 입력은 비우며 저장 입력은 새로고침 후 복원한다. 예시에서 유입 원자료로 되돌리면 가상 분쟁도 비운다.

## 실제 모델/API 검사

test_relief_forecast.py20/20 통과. 기준 주1행과 같은 값4행의 예측 일치, 이전3주만 변경 시 모든 예측 일치, 기준 주 변경 시 예측 변화,1행의 provenance/안내, 부적합 길이와 음수/문자/불리언 거부를 포함한다. 기존 일별 특징/재귀/미래 실제값 누수 차단/2주 결과 유지 검사도 통과했다.

기존 Node 회귀15/15, TypeScript noEmit 및 Vite build 통과. 빌드는 기존 큰 번들/미래 설정 경고를 출력한다. Python은 기존 라이브러리 deprecation 및 pytest 캐시 쓰기 경고가 있지만 검사 실패는 없다.

## 브라우저 확인

실제 모델 API8000을 수정본으로 재시작하고 프런트8443에서 실행했다. 입력 누락/음수 차단, 예시 버튼, 새로고침 후 유입/분쟁 보존, 가상 분쟁 복구를 확인했다.

유입량을 그대로 두고 분쟁만 바꿨을 때의 결과:

| 시연용 사건 수/사망자 수 | 1주 후 총 예측 | 2주 후 | 3주 후 | 4주 후 | 4주 총합 |
|---|---:|---:|---:|---:|---:|
|1000/100|5020|5154|5199|5235|20608|
|4000/1000|5259|5230|5209|5132|20830|

큰 값이 항상 각 거점의 예측을 증가시키는 것은 아니다. 이 비교는 입력 연결과 모델 민감도를 확인하는 합성 시연이며 분쟁 영향의 인과관계를 입증하지 않는다. 원자료 미래값으로 정확도를 평가한 실험도 아니다.

변경한 두 번째 예측에서 추가 입력 없이 Step03 예시→최적화 결과까지 확인했다. Medyka 이용자956명,16회 운행, 모형 총비용 표시는57,618달러, 수요 충족69.2%. 차량 적재·시각과 지도 경로가 표시됐다. 결과 DOM/입력·결과 스크린샷은 같은 폴더에 저장했다. 브라우저 오류 로그0건이다.

이전 보고서 WAPE20.15%는 번들의 전형적 분쟁 수준을 가정한 평가다. 이번 UI에서 입력하는 실제 분쟁 자료의 성능을 검증한 수치로 사용하지 않는다. 최적화 엔진/검증 기록, 모델 가중치, 기존 FINAL ZIP/PDF는 변경하지 않았다. 실제 배송시간·지급비용·현장 효과는 여전히 미입증이다.
