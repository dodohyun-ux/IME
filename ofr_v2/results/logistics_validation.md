# 물류 제약 검증 기록 — 2026-10-02

실제 폴란드 물류 운영값을 확보한 성과평가가 아니라, 구현한 수식과 데이터
흐름의 검증 기록이다. 공식 근거와 수식은 `../docs/logistics_constraints.md`.
예측모델과 기존 홀드아웃 결과는 변경하지 않았다.

## 재현 명령

```text
python -m pytest ofr_v2/tests -q
python scripts/verify_logistics_scenarios.py
cd ofr_v2/app/frontend
npm ci --ignore-scripts
npx tsc --noEmit
npm run build
```

32개 제약/API 테스트를 통과했다. Python 3.12, SciPy 1.18.1,
FastAPI 0.141.1 환경에서 확인했다. HTTP 테스트는 예측 모델 파일 로딩을
격리하고 실제 최적화 솔버를 호출한다. 따라서 예측모델 검증 결과로 해석하지 않는다.
기존 `scripts/smoke_backend.py`는 실제 LFS 모델이 있는 CI에서 그대로 실행된다.

프론트 타입 검사와 Vite 8.2.2 프로덕션 빌드를 통과했다(Node 24.19.0).
기존 Vite 구성의 향후 native loader 호환성과 번들 크기 경고는 남는다.
기존 CI는 Node 22를 사용한다.

`scripts/check_logistics_ui.cjs`를 실행해 입력→요청 매핑→결과 렌더링을
headless Edge로 확인했다. 이 테스트의 예측과 HTTP 응답은 명시적인 fixture다.
최적화 HTTP 계약은 별도 Python 테스트가 실제 솔버로 검증한다. 공개 Vercel과
공개 백엔드의 실제 배포 후 종단 간 확인은 이 기록에 포함하지 않는다.

## 합성 비교 예제

`logistics_synthetic_validation.csv`는 동일 예측·재고·공급·예산을 사용하고
물류 조건만 변경한 결과다. `scripts/verify_logistics_scenarios.py`로 재생성한다.

| 조건 | 정규화 수요 충족률 | 가장 큰 품목/주 부족률 | 총비용 |
|---|---:|---:|---:|
| 기존 모델 | 73.83% | 26.25% | 110,000 |
| 운송비 포함 | 73.30% | 26.79% | 110,000 |
| 조달 7일 추가 | 76.48% | 62.50% | 110,000 |
| 노선 전체 폐쇄 | 14.89% | 89.74% | 0 |
| 물/식량 잔여기한 7일, 운송 7일 | 50.23% | 81.67% | 57,250 |

조달 지연 사례에서 평균 충족률이 상승해도 좋은 계획이라는 뜻은 아니다.
최우선인 최대부족률이 26.79%에서 62.50%로 악화했고, 그 수준을 고정한 후
평균 충족률을 최적화하기 때문에 이런 수치가 가능하다. 공정성 우선의
서로 다른 목적 단계를 하나의 평균으로 평가하지 않는다.

폐쇄 사례는 **이미 있는 재고**만 지급한다. 기한 사례는 운송 종료 시 기한이
끝나는 물/식량 신규 주문을 차단하고 다른 품목·기존 재고를 사용한다.
기존 배치가 이미 만료됐거나 남아서 만료되는 경우는 자동 테스트가 별도로
확인한다. 기존 모델 대비 비용/품질의 개선 실적으로 발표해서는 안 된다.

## 운영에 필요한 추가 자료

차량의 실제 적재중량/부피와 포장 단위별 중량, 기관에 할당된 통과량,
계약의 조달·운송기간, 기존 예약과 배치별 만료일, 폐기 가능량·비용을
현장 기록으로 교체해야 한다. 주간 보수화 오차와 노선/배치 규모 증가 시
실행시간을 추가 측정해야 한다. 현재는 선택 구호소 하나의 시나리오다.
