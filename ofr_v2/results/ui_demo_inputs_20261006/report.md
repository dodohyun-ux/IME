# 예시 입력 버튼 동작 확인 — 2026-10-06

사용자 요청: 첫 화면 CSV 업로드를 없애고 예측/최적화 입력 화면에 각각 한 번에 필요한 값을 채우는 버튼을 제공한다. 기존 디자인을 유지한다.

## 변경

- Step01 CSV 버튼·파일 입력·업로드 핸들러 제거. 수동 입력은 유지한다. 보존된 CSV 파서 유틸리티는 화면에서 호출되지 않는다.
- Step01 예시 버튼: 기준 주 2026-01-26; 기준 주/1주 전 Medyka 2000/1800, Dorohusk 1600/1450, Korczowa 1350/1200명. 이용률10%, 체류3일. 실제 관측으로 주장하지 않는 가상 시연값이다.
- Step03 예시 버튼: 모든 거점의 재고/창고, 4주 공급, 단가/부피, 예산110000달러, 공정성 우선, 품목별 중량/조달/기한/폐기, 이용률10%/체류3일을 채운다. 물류는 새 도로 모드·Lwowska36·차량2대·다음 날 복귀/중간 휴식 허용 시나리오로 초기화한다. 속도/비용은 기존 출처 표시된 시나리오 기본값을 사용한다. 기존 상세 JSON/비활성/주별 모드 값이 남지 않는다.
- 선택 거점과 실제 계산된 예측을 유지한다. 최적화 결과 확인 버튼에서 실제 엔진을 호출한다. 예측 숫자나 최적화 결과를 미리 저장해 보여주지 않는다.
- 예시 출처를 입력과 예측 화면에 표시하고 저장 실제값 비교를 끈다. 새로고침 시 예시는 보존하지만 예측은 재계산한다. 원자료 복구 때 계산을 잠시 막고 원자료를 다시 불러온다.

## 브라우저 확인

로컬 프런트 http://127.0.0.1:8443/ 및 기존 실제 모델 API에서 수행했다.

1. 첫 화면 CSV 업로드 없음, 예시 버튼 한 개.
2. 예시 버튼 한 번으로 6칸과 기준 주가 채워지고 예측 CTA 활성화.
3. 새로고침 뒤에도 가상 예시 표시/숫자 보존, 저장 원자료가 덮어쓰지 않음.
4. 추가 숫자 입력 없이 예측 실행: 4주 총 유입 20,227명; 주별 총 5,002/5,067/5,077/5,081명. 기존 제공 모델의 계산 결과다.
5. Step03에서 차량 대수0과 운송 적용 해제를 일부러 설정한 뒤 예시 버튼 클릭. 운송 적용/도로 모드/차량2대/Lwowska36로 복구.
6. 추가 입력 없이 최적화 CTA 실행: Medyka 16회 운행, 총 조달·운송·폐기 모형비용 57,565.37달러, 표시 수요 충족80.1%, 차량 적재/출발·도착·복귀/지도 경로 표시.
7. 원자료 복구 버튼으로 실제 저장 유입 1963/1818,1688/1489,1327/1204가 돌아오는 것 확인.
8. 브라우저 오류 로그0. 각 입력 화면과 결과 화면 스크린샷을 같은 폴더에 저장했다. result_dom.txt는 결과 화면의 읽기 전용 DOM 기록이다.

## 코드 검사와 범위

기존 Node 입력·물류·응답 경합 회귀 검사15/15 통과, TypeScript 검사 및 Vite 프로덕션 빌드 통과. 빌드는 기존 큰 번들/미래 Vite 설정 경고를 출력한다. CSV 유틸리티 검사는 보존 코드의 회귀 검사이며 제거한 UI 기능의 제공을 뜻하지 않는다.

이번 변경은 UI 편의 기능이다. 예측 가중치·추론식·최적화 엔진과 이전 성능 지표를 변경하지 않았다. 실제 배송/지급비용/현장 효과의 새 실측 검증이 아니다. 기존 FINAL ZIP과 검증 PDF는 수정 전 산출물로 보존한다.
